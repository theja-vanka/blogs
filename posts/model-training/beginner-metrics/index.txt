<section id="introduction" class="level2">
<h2 class="anchored" data-anchor-id="introduction" id="introduction">Introduction</h2>
<p>When you train a machine learning model, numbers fly by in your terminal: loss, accuracy, learning rate, gradient norms. Staring at scrolling text is a terrible way to understand whether your model is actually learning. You need pictures — loss curves that trend downward, histograms that show whether your gradients are exploding or vanishing, and dashboards that let you compare one experiment against another.</p>
<p>This guide walks through the two most common tools for this job: <strong>TensorBoard</strong>, the visualization toolkit that started with TensorFlow but is now a first-class citizen in the PyTorch ecosystem, and <strong>MLflow</strong>, a full experiment-tracking platform that goes beyond plots into reproducibility and model management. Along the way, you’ll learn how to log metrics from plain PyTorch, how PyTorch Lightning makes this dramatically easier, and how to track the “boring but important” signals — gradient flow, weight distributions, learning rate schedules, images, and GPU utilization — that often reveal problems long before your loss curve does.</p>
<p>By the end, you should be able to:</p>
<ul>
<li>Set up TensorBoard and log scalars, histograms, images, and more from raw PyTorch.</li>
<li>Use PyTorch Lightning’s built-in logging so you write less boilerplate.</li>
<li>Diagnose training problems using gradient flow and weight histogram visualizations.</li>
<li>Track GPU/compute metrics alongside your training metrics.</li>
<li>Set up MLflow for experiment tracking, parameter logging, and model versioning.</li>
<li>Understand when to reach for TensorBoard versus MLflow (or both).</li>
</ul>
<p>No prior experience with either tool is assumed. Basic familiarity with PyTorch (writing a training loop, defining a model) is helpful but not strictly required — we’ll explain each snippet as we go.</p>
</section>
</section>
<section id="part-1-tensorboard" class="level1">
<h1>Part 1: TensorBoard</h1>
<section id="what-tensorboard-actually-is" class="level2">
<h2 class="anchored" data-anchor-id="what-tensorboard-actually-is" id="what-tensorboard-actually-is">What TensorBoard actually is</h2>
<p>TensorBoard is a local web application. You run a small Python script (or a training job) that writes special log files called <strong>event files</strong> to a directory. TensorBoard reads that directory and renders the contents as interactive charts in your browser. It is not a cloud service and it does not track your experiments across machines by default — it’s a visualization layer on top of files sitting on your disk.</p>
<p>The key building blocks are:</p>
<ul>
<li><strong><code>SummaryWriter</code></strong>: the Python object you use to write data to the log directory (often called <code>runs/</code> or <code>logs/</code>).</li>
<li><strong>The log directory</strong>: a folder full of event files, one “run” per subfolder typically.</li>
<li><strong>The TensorBoard server</strong>: a command-line tool (<code>tensorboard --logdir=...</code>) that reads the log directory and serves a dashboard.</li>
</ul>
</section>
<section id="installing-tensorboard" class="level2">
<h2 class="anchored" data-anchor-id="installing-tensorboard" id="installing-tensorboard">Installing TensorBoard</h2>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb1"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb1-1"><a href="#cb1-1" aria-hidden="true" tabindex="-1"></a><span class="ex">pip</span> install tensorboard</span></code></pre></div></div>
<p>If you’re using PyTorch, you don’t need TensorFlow installed — PyTorch ships its own lightweight <code>SummaryWriter</code> in <code>torch.utils.tensorboard</code> that writes TensorBoard-compatible event files.</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb2"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb2-1"><a href="#cb2-1" aria-hidden="true" tabindex="-1"></a><span class="ex">pip</span> install torch torchvision tensorboard</span></code></pre></div></div>
</section>
<section id="your-first-scalar-logging-loss" class="level2">
<h2 class="anchored" data-anchor-id="your-first-scalar-logging-loss" id="your-first-scalar-logging-loss">Your first scalar: logging loss</h2>
<p>Let’s start with the simplest possible example — logging a training loss value at every step.</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb3"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb3-1"><a href="#cb3-1" aria-hidden="true" tabindex="-1"></a><span class="im">from</span> torch.utils.tensorboard <span class="im">import</span> SummaryWriter</span>
<span id="cb3-2"><a href="#cb3-2" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb3-3"><a href="#cb3-3" aria-hidden="true" tabindex="-1"></a><span class="co"># Creates (or reuses) a directory called "runs/experiment_1"</span></span>
<span id="cb3-4"><a href="#cb3-4" aria-hidden="true" tabindex="-1"></a>writer <span class="op">=</span> SummaryWriter(log_dir<span class="op">=</span><span class="st">"runs/experiment_1"</span>)</span>
<span id="cb3-5"><a href="#cb3-5" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb3-6"><a href="#cb3-6" aria-hidden="true" tabindex="-1"></a><span class="cf">for</span> step <span class="kw">in</span> <span class="bu">range</span>(<span class="dv">100</span>):</span>
<span id="cb3-7"><a href="#cb3-7" aria-hidden="true" tabindex="-1"></a>    fake_loss <span class="op">=</span> <span class="fl">1.0</span> <span class="op">/</span> (step <span class="op">+</span> <span class="dv">1</span>)  <span class="co"># pretend this is coming from training</span></span>
<span id="cb3-8"><a href="#cb3-8" aria-hidden="true" tabindex="-1"></a>    writer.add_scalar(<span class="st">"Loss/train"</span>, fake_loss, step)</span>
<span id="cb3-9"><a href="#cb3-9" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb3-10"><a href="#cb3-10" aria-hidden="true" tabindex="-1"></a>writer.close()</span></code></pre></div></div>
<p>A few things to note:</p>
<ul>
<li><code>add_scalar(tag, value, step)</code> takes a <strong>tag</strong> (a name for the metric, which can include a <code>/</code> to create a grouping in the UI, like <code>Loss/train</code> vs <code>Loss/val</code>), the <strong>value</strong> at this point, and the <strong>step</strong> (usually the training iteration or epoch number) — this becomes the x-axis.</li>
<li>You must call <code>writer.close()</code> (or use it as a context manager) so all buffered data gets flushed to disk.</li>
<li>Always call <code>SummaryWriter</code> <strong>once</strong> per run and reuse it — creating a new one every step is a common beginner mistake that fragments your logs.</li>
</ul>
<p>To view this, run in a terminal from the same working directory:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb4"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb4-1"><a href="#cb4-1" aria-hidden="true" tabindex="-1"></a><span class="ex">tensorboard</span> <span class="at">--logdir</span><span class="op">=</span>runs</span></code></pre></div></div>
<p>Then open the URL it prints (usually <code>http://localhost:6006</code>) in your browser. You’ll see a “Loss” section with a smooth downward curve.</p>
</section>
<section id="logging-metrics-inside-a-real-pytorch-training-loop" class="level2">
<h2 class="anchored" data-anchor-id="logging-metrics-inside-a-real-pytorch-training-loop" id="logging-metrics-inside-a-real-pytorch-training-loop">Logging metrics inside a real PyTorch training loop</h2>
<p>Here’s a more realistic example — a small classifier trained on random data, logging both training and validation loss/accuracy per epoch.</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb5"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb5-1"><a href="#cb5-1" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> torch</span>
<span id="cb5-2"><a href="#cb5-2" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> torch.nn <span class="im">as</span> nn</span>
<span id="cb5-3"><a href="#cb5-3" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> torch.optim <span class="im">as</span> optim</span>
<span id="cb5-4"><a href="#cb5-4" aria-hidden="true" tabindex="-1"></a><span class="im">from</span> torch.utils.tensorboard <span class="im">import</span> SummaryWriter</span>
<span id="cb5-5"><a href="#cb5-5" aria-hidden="true" tabindex="-1"></a><span class="im">from</span> torch.utils.data <span class="im">import</span> DataLoader, TensorDataset</span>
<span id="cb5-6"><a href="#cb5-6" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-7"><a href="#cb5-7" aria-hidden="true" tabindex="-1"></a><span class="co"># --- Fake data for illustration ---</span></span>
<span id="cb5-8"><a href="#cb5-8" aria-hidden="true" tabindex="-1"></a>X_train <span class="op">=</span> torch.randn(<span class="dv">1000</span>, <span class="dv">20</span>)</span>
<span id="cb5-9"><a href="#cb5-9" aria-hidden="true" tabindex="-1"></a>y_train <span class="op">=</span> torch.randint(<span class="dv">0</span>, <span class="dv">2</span>, (<span class="dv">1000</span>,))</span>
<span id="cb5-10"><a href="#cb5-10" aria-hidden="true" tabindex="-1"></a>X_val <span class="op">=</span> torch.randn(<span class="dv">200</span>, <span class="dv">20</span>)</span>
<span id="cb5-11"><a href="#cb5-11" aria-hidden="true" tabindex="-1"></a>y_val <span class="op">=</span> torch.randint(<span class="dv">0</span>, <span class="dv">2</span>, (<span class="dv">200</span>,))</span>
<span id="cb5-12"><a href="#cb5-12" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-13"><a href="#cb5-13" aria-hidden="true" tabindex="-1"></a>train_loader <span class="op">=</span> DataLoader(TensorDataset(X_train, y_train), batch_size<span class="op">=</span><span class="dv">32</span>, shuffle<span class="op">=</span><span class="va">True</span>)</span>
<span id="cb5-14"><a href="#cb5-14" aria-hidden="true" tabindex="-1"></a>val_loader <span class="op">=</span> DataLoader(TensorDataset(X_val, y_val), batch_size<span class="op">=</span><span class="dv">32</span>)</span>
<span id="cb5-15"><a href="#cb5-15" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-16"><a href="#cb5-16" aria-hidden="true" tabindex="-1"></a>model <span class="op">=</span> nn.Sequential(</span>
<span id="cb5-17"><a href="#cb5-17" aria-hidden="true" tabindex="-1"></a>    nn.Linear(<span class="dv">20</span>, <span class="dv">64</span>),</span>
<span id="cb5-18"><a href="#cb5-18" aria-hidden="true" tabindex="-1"></a>    nn.ReLU(),</span>
<span id="cb5-19"><a href="#cb5-19" aria-hidden="true" tabindex="-1"></a>    nn.Linear(<span class="dv">64</span>, <span class="dv">2</span>),</span>
<span id="cb5-20"><a href="#cb5-20" aria-hidden="true" tabindex="-1"></a>)</span>
<span id="cb5-21"><a href="#cb5-21" aria-hidden="true" tabindex="-1"></a>optimizer <span class="op">=</span> optim.Adam(model.parameters(), lr<span class="op">=</span><span class="fl">1e-3</span>)</span>
<span id="cb5-22"><a href="#cb5-22" aria-hidden="true" tabindex="-1"></a>criterion <span class="op">=</span> nn.CrossEntropyLoss()</span>
<span id="cb5-23"><a href="#cb5-23" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-24"><a href="#cb5-24" aria-hidden="true" tabindex="-1"></a>writer <span class="op">=</span> SummaryWriter(log_dir<span class="op">=</span><span class="st">"runs/classifier_experiment"</span>)</span>
<span id="cb5-25"><a href="#cb5-25" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-26"><a href="#cb5-26" aria-hidden="true" tabindex="-1"></a>global_step <span class="op">=</span> <span class="dv">0</span></span>
<span id="cb5-27"><a href="#cb5-27" aria-hidden="true" tabindex="-1"></a><span class="cf">for</span> epoch <span class="kw">in</span> <span class="bu">range</span>(<span class="dv">10</span>):</span>
<span id="cb5-28"><a href="#cb5-28" aria-hidden="true" tabindex="-1"></a>    <span class="co"># --- Training ---</span></span>
<span id="cb5-29"><a href="#cb5-29" aria-hidden="true" tabindex="-1"></a>    model.train()</span>
<span id="cb5-30"><a href="#cb5-30" aria-hidden="true" tabindex="-1"></a>    <span class="cf">for</span> xb, yb <span class="kw">in</span> train_loader:</span>
<span id="cb5-31"><a href="#cb5-31" aria-hidden="true" tabindex="-1"></a>        optimizer.zero_grad()</span>
<span id="cb5-32"><a href="#cb5-32" aria-hidden="true" tabindex="-1"></a>        preds <span class="op">=</span> model(xb)</span>
<span id="cb5-33"><a href="#cb5-33" aria-hidden="true" tabindex="-1"></a>        loss <span class="op">=</span> criterion(preds, yb)</span>
<span id="cb5-34"><a href="#cb5-34" aria-hidden="true" tabindex="-1"></a>        loss.backward()</span>
<span id="cb5-35"><a href="#cb5-35" aria-hidden="true" tabindex="-1"></a>        optimizer.step()</span>
<span id="cb5-36"><a href="#cb5-36" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-37"><a href="#cb5-37" aria-hidden="true" tabindex="-1"></a>        <span class="co"># Log loss at every training step (fine-grained view)</span></span>
<span id="cb5-38"><a href="#cb5-38" aria-hidden="true" tabindex="-1"></a>        writer.add_scalar(<span class="st">"Loss/train_step"</span>, loss.item(), global_step)</span>
<span id="cb5-39"><a href="#cb5-39" aria-hidden="true" tabindex="-1"></a>        global_step <span class="op">+=</span> <span class="dv">1</span></span>
<span id="cb5-40"><a href="#cb5-40" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-41"><a href="#cb5-41" aria-hidden="true" tabindex="-1"></a>    <span class="co"># --- Validation ---</span></span>
<span id="cb5-42"><a href="#cb5-42" aria-hidden="true" tabindex="-1"></a>    model.<span class="bu">eval</span>()</span>
<span id="cb5-43"><a href="#cb5-43" aria-hidden="true" tabindex="-1"></a>    val_loss_total, correct, total <span class="op">=</span> <span class="fl">0.0</span>, <span class="dv">0</span>, <span class="dv">0</span></span>
<span id="cb5-44"><a href="#cb5-44" aria-hidden="true" tabindex="-1"></a>    <span class="cf">with</span> torch.no_grad():</span>
<span id="cb5-45"><a href="#cb5-45" aria-hidden="true" tabindex="-1"></a>        <span class="cf">for</span> xb, yb <span class="kw">in</span> val_loader:</span>
<span id="cb5-46"><a href="#cb5-46" aria-hidden="true" tabindex="-1"></a>            preds <span class="op">=</span> model(xb)</span>
<span id="cb5-47"><a href="#cb5-47" aria-hidden="true" tabindex="-1"></a>            val_loss_total <span class="op">+=</span> criterion(preds, yb).item() <span class="op">*</span> xb.size(<span class="dv">0</span>)</span>
<span id="cb5-48"><a href="#cb5-48" aria-hidden="true" tabindex="-1"></a>            correct <span class="op">+=</span> (preds.argmax(dim<span class="op">=</span><span class="dv">1</span>) <span class="op">==</span> yb).<span class="bu">sum</span>().item()</span>
<span id="cb5-49"><a href="#cb5-49" aria-hidden="true" tabindex="-1"></a>            total <span class="op">+=</span> xb.size(<span class="dv">0</span>)</span>
<span id="cb5-50"><a href="#cb5-50" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-51"><a href="#cb5-51" aria-hidden="true" tabindex="-1"></a>    val_loss <span class="op">=</span> val_loss_total <span class="op">/</span> total</span>
<span id="cb5-52"><a href="#cb5-52" aria-hidden="true" tabindex="-1"></a>    val_acc <span class="op">=</span> correct <span class="op">/</span> total</span>
<span id="cb5-53"><a href="#cb5-53" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-54"><a href="#cb5-54" aria-hidden="true" tabindex="-1"></a>    <span class="co"># Log epoch-level metrics (coarser view, one point per epoch)</span></span>
<span id="cb5-55"><a href="#cb5-55" aria-hidden="true" tabindex="-1"></a>    writer.add_scalar(<span class="st">"Loss/val"</span>, val_loss, epoch)</span>
<span id="cb5-56"><a href="#cb5-56" aria-hidden="true" tabindex="-1"></a>    writer.add_scalar(<span class="st">"Accuracy/val"</span>, val_acc, epoch)</span>
<span id="cb5-57"><a href="#cb5-57" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-58"><a href="#cb5-58" aria-hidden="true" tabindex="-1"></a>    <span class="bu">print</span>(<span class="ss">f"Epoch </span><span class="sc">{</span>epoch<span class="sc">}</span><span class="ss">: val_loss=</span><span class="sc">{</span>val_loss<span class="sc">:.4f}</span><span class="ss">, val_acc=</span><span class="sc">{</span>val_acc<span class="sc">:.4f}</span><span class="ss">"</span>)</span>
<span id="cb5-59"><a href="#cb5-59" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb5-60"><a href="#cb5-60" aria-hidden="true" tabindex="-1"></a>writer.close()</span></code></pre></div></div>
<p>Notice the pattern: <strong>fine-grained metrics</strong> (per training step, like the raw loss) are useful for spotting instability early in training, while <strong>coarse-grained metrics</strong> (per epoch, like validation accuracy) are useful for tracking overall progress. It’s common — and a good habit — to log both, using different step counters (<code>global_step</code> for training steps, <code>epoch</code> for epoch-level metrics) so the x-axes don’t get mixed up.</p>
</section>

<section id="logging-gradient-flow" class="level2">
<h2 class="anchored" data-anchor-id="logging-gradient-flow" id="logging-gradient-flow">Logging gradient flow</h2>
<p>Gradient flow is one of the most useful — and most overlooked — things to visualize. If gradients vanish (become near-zero) or explode (become huge) in certain layers, training will stall or diverge, often without an obvious symptom in the loss curve until it’s too late.</p>
<p>The simplest approach is to log the <strong>norm</strong> of each parameter’s gradient after <code>backward()</code>:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb13"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb13-1"><a href="#cb13-1" aria-hidden="true" tabindex="-1"></a>loss.backward()</span>
<span id="cb13-2"><a href="#cb13-2" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb13-3"><a href="#cb13-3" aria-hidden="true" tabindex="-1"></a><span class="cf">for</span> name, param <span class="kw">in</span> model.named_parameters():</span>
<span id="cb13-4"><a href="#cb13-4" aria-hidden="true" tabindex="-1"></a>    <span class="cf">if</span> param.grad <span class="kw">is</span> <span class="kw">not</span> <span class="va">None</span>:</span>
<span id="cb13-5"><a href="#cb13-5" aria-hidden="true" tabindex="-1"></a>        writer.add_scalar(<span class="ss">f"grad_norm/</span><span class="sc">{</span>name<span class="sc">}</span><span class="ss">"</span>, param.grad.norm(), global_step)</span>
<span id="cb13-6"><a href="#cb13-6" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb13-7"><a href="#cb13-7" aria-hidden="true" tabindex="-1"></a>optimizer.step()</span></code></pre></div></div>
<p>You can also log the full gradient distribution as a histogram, which shows not just the magnitude but the shape:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb14"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb14-1"><a href="#cb14-1" aria-hidden="true" tabindex="-1"></a><span class="cf">for</span> name, param <span class="kw">in</span> model.named_parameters():</span>
<span id="cb14-2"><a href="#cb14-2" aria-hidden="true" tabindex="-1"></a>    <span class="cf">if</span> param.grad <span class="kw">is</span> <span class="kw">not</span> <span class="va">None</span>:</span>
<span id="cb14-3"><a href="#cb14-3" aria-hidden="true" tabindex="-1"></a>        writer.add_histogram(<span class="ss">f"grad_hist/</span><span class="sc">{</span>name<span class="sc">}</span><span class="ss">"</span>, param.grad, global_step)</span></code></pre></div></div>
<p>A classic and very readable way to see gradient flow across <em>all layers at once</em> is to compute the average absolute gradient per layer and plot it as a bar-style line — this pattern is popular enough that it’s worth writing as a reusable helper:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb15"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb15-1"><a href="#cb15-1" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> numpy <span class="im">as</span> np</span>
<span id="cb15-2"><a href="#cb15-2" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> matplotlib.pyplot <span class="im">as</span> plt</span>
<span id="cb15-3"><a href="#cb15-3" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb15-4"><a href="#cb15-4" aria-hidden="true" tabindex="-1"></a><span class="kw">def</span> plot_grad_flow(named_parameters):</span>
<span id="cb15-5"><a href="#cb15-5" aria-hidden="true" tabindex="-1"></a>    <span class="co">"""Plots the average gradient magnitude per layer.</span></span>
<span id="cb15-6"><a href="#cb15-6" aria-hidden="true" tabindex="-1"></a><span class="co">    Call this after loss.backward() and before optimizer.step()."""</span></span>
<span id="cb15-7"><a href="#cb15-7" aria-hidden="true" tabindex="-1"></a>    avg_grads <span class="op">=</span> []</span>
<span id="cb15-8"><a href="#cb15-8" aria-hidden="true" tabindex="-1"></a>    layers <span class="op">=</span> []</span>
<span id="cb15-9"><a href="#cb15-9" aria-hidden="true" tabindex="-1"></a>    <span class="cf">for</span> name, param <span class="kw">in</span> named_parameters:</span>
<span id="cb15-10"><a href="#cb15-10" aria-hidden="true" tabindex="-1"></a>        <span class="cf">if</span> param.requires_grad <span class="kw">and</span> param.grad <span class="kw">is</span> <span class="kw">not</span> <span class="va">None</span> <span class="kw">and</span> <span class="st">"bias"</span> <span class="kw">not</span> <span class="kw">in</span> name:</span>
<span id="cb15-11"><a href="#cb15-11" aria-hidden="true" tabindex="-1"></a>            layers.append(name)</span>
<span id="cb15-12"><a href="#cb15-12" aria-hidden="true" tabindex="-1"></a>            avg_grads.append(param.grad.<span class="bu">abs</span>().mean().item())</span>
<span id="cb15-13"><a href="#cb15-13" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb15-14"><a href="#cb15-14" aria-hidden="true" tabindex="-1"></a>    fig, ax <span class="op">=</span> plt.subplots(figsize<span class="op">=</span>(<span class="dv">10</span>, <span class="dv">5</span>))</span>

<p><code>add_figure</code> accepts a Matplotlib figure directly, which is convenient any time you want a custom plot (not just the built-in scalar/histogram views) inside TensorBoard.</p>
<p><strong>What to look for:</strong> if the average gradient magnitude is near zero for early layers but healthy for later ones, that’s a textbook vanishing-gradient signature — common in deep networks without residual connections or proper normalization. If magnitudes are enormous or <code>NaN</code>, you’re looking at exploding gradients, and gradient clipping (<code>torch.nn.utils.clip_grad_norm_</code>) is a typical fix.</p>

<h1>Part 2: Logging Metrics with PyTorch Lightning</h1>
<section id="why-lightning" class="level2">
<h2 class="anchored" data-anchor-id="why-lightning" id="why-lightning">Why Lightning?</h2>
<p>Everything above works, but you’ll notice a pattern: every training loop needs the same boilerplate — moving tensors to the right device, zeroing gradients, stepping the optimizer, computing epoch averages, calling <code>writer.add_scalar</code> in a dozen places. PyTorch Lightning is a lightweight wrapper around PyTorch that removes this boilerplate by organizing your code into a <code>LightningModule</code>, and — crucially for this guide — it comes with a unified logging API that automatically works with TensorBoard, MLflow, and several other backends without changing your logging calls.</p>

</section>

<span id="cb21-53"><a href="#cb21-53" aria-hidden="true" tabindex="-1"></a>trainer <span class="op">=</span> L.Trainer(max_epochs<span class="op">=</span><span class="dv">10</span>, log_every_n_steps<span class="op">=</span><span class="dv">10</span>)</span>
<span id="cb21-54"><a href="#cb21-54" aria-hidden="true" tabindex="-1"></a>trainer.fit(model, train_loader, val_loader)</span></code></pre></div></div>
<p>That’s the entire training script. By default, Lightning creates a <code>lightning_logs/</code> directory and uses TensorBoard as the logger automatically — no <code>SummaryWriter</code> needed. Run:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb22"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb22-1"><a href="#cb22-1" aria-hidden="true" tabindex="-1"></a><span class="ex">tensorboard</span> <span class="at">--logdir</span><span class="op">=</span>lightning_logs</span></code></pre></div></div>
<p>and you’ll see the same kind of dashboard as before, generated with far less code.</p>

<section id="understanding-self.log" class="level2">
<h2 class="anchored" data-anchor-id="understanding-self.log" id="understanding-self.log">Understanding <code>self.log()</code></h2>
<p>The single method <code>self.log(name, value, ...)</code> is the heart of Lightning’s logging system. Key arguments:</p>
<ul>
<li><code>on_step</code>: log this value at every batch/step.</li>
<li><code>on_epoch</code>: aggregate (by default, averaged) this value over the epoch and log once per epoch.</li>
<li><code>prog_bar</code>: also show this value in the terminal progress bar, for a quick sanity check while training.</li>
<li><code>logger</code>: whether to send this to the configured logger(s) at all (default <code>True</code>).</li>
</ul>
<p>You can log a whole dictionary at once with <code>self.log_dict</code>:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb23"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb23-1"><a href="#cb23-1" aria-hidden="true" tabindex="-1"></a><span class="va">self</span>.log_dict(</span>
<span id="cb23-2"><a href="#cb23-2" aria-hidden="true" tabindex="-1"></a>    {<span class="st">"val_loss"</span>: loss, <span class="st">"val_acc"</span>: acc, <span class="st">"val_f1"</span>: f1},</span>
<span id="cb23-3"><a href="#cb23-3" aria-hidden="true" tabindex="-1"></a>    on_epoch<span class="op">=</span><span class="va">True</span>,</span>
<span id="cb23-4"><a href="#cb23-4" aria-hidden="true" tabindex="-1"></a>    prog_bar<span class="op">=</span><span class="va">True</span>,</span>
<span id="cb23-5"><a href="#cb23-5" aria-hidden="true" tabindex="-1"></a>)</span></code></pre></div></div>
</section>

<p>By default Lightning uses <code>TensorBoardLogger</code>, but you can be explicit, configure it, or swap in a different backend entirely — including MLflow, which we’ll set up properly in Part 3.</p>

<span id="cb24-2"><a href="#cb24-2" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb24-3"><a href="#cb24-3" aria-hidden="true" tabindex="-1"></a>tb_logger <span class="op">=</span> TensorBoardLogger(save_dir<span class="op">=</span><span class="st">"logs"</span>, name<span class="op">=</span><span class="st">"my_experiment"</span>)</span>

<span id="cb24-11"><a href="#cb24-11" aria-hidden="true" tabindex="-1"></a>    max_epochs<span class="op">=</span><span class="dv">10</span>,</span>
<span id="cb24-12"><a href="#cb24-12" aria-hidden="true" tabindex="-1"></a>    logger<span class="op">=</span>[tb_logger, mlf_logger],  <span class="co"># log to both simultaneously!</span></span>

You don’t need separate TensorBoard and MLflow logging calls scattered through your training loop.</p>

<section id="part-3-mlflow" class="level1">
<h1>Part 3: MLflow</h1>
<section id="what-mlflow-is-and-how-it-differs-from-tensorboard" class="level2">
<h2 class="anchored" data-anchor-id="what-mlflow-is-and-how-it-differs-from-tensorboard" id="what-mlflow-is-and-how-it-differs-from-tensorboard">What MLflow is, and how it differs from TensorBoard</h2>
<p>TensorBoard is primarily a <strong>visualization</strong> tool: point it at event files, get charts. MLflow is a broader <strong>experiment tracking and lifecycle management</strong> platform. It still gives you charts, but it also gives you:</p>
<ul>
<li>A structured way to log <strong>parameters</strong> (hyperparameters), <strong>metrics</strong> (time-series values, like TensorBoard scalars), and <strong>artifacts</strong> (files — model checkpoints, plots, datasets).</li>
<li>A <strong>Tracking Server</strong> with a UI, backed by a database or filesystem, that stores every run’s parameters/metrics/artifacts in a queryable way — so you can filter and sort runs, not just eyeball overlaid line charts.</li>
<li>A <strong>Model Registry</strong> for versioning trained models, tagging them (<code>staging</code>, <code>production</code>), and managing their lifecycle — something TensorBoard has no concept of at all.</li>
<li>First-class support for <strong>team collaboration</strong>: a shared MLflow tracking server means everyone on a team sees the same experiment history, rather than everyone having their own local <code>runs/</code> folder.</li>
</ul>
<p>A simple way to think about it: TensorBoard answers “what did my loss curve look like?” MLflow answers that too, but also “which of my 40 experiments had the best validation accuracy, what hyperparameters did it use, and where’s the model file?”</p>
</section>
<section id="installing-and-running-mlflow" class="level2">
<h2 class="anchored" data-anchor-id="installing-and-running-mlflow" id="installing-and-running-mlflow">Installing and running MLflow</h2>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb30"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb30-1"><a href="#cb30-1" aria-hidden="true" tabindex="-1"></a><span class="ex">pip</span> install mlflow</span></code></pre></div></div>
<p>MLflow needs a <strong>tracking URI</strong> — where to store run data. The simplest option, especially while learning, is a local folder:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb31"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb31-1"><a href="#cb31-1" aria-hidden="true" tabindex="-1"></a><span class="ex">mlflow</span> ui <span class="at">--backend-store-uri</span> file:./mlruns</span></code></pre></div></div>
<p>This starts a web UI (usually at <code>http://localhost:5000</code>) reading from a local <code>mlruns/</code> directory that MLflow creates automatically when you start logging.</p>
<p>For a shared/team setup, you’d instead run a proper tracking server backed by a database:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb32"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb32-1"><a href="#cb32-1" aria-hidden="true" tabindex="-1"></a><span class="ex">mlflow</span> server <span class="dt">\</span></span>

<span id="cb32-4"><a href="#cb32-4" aria-hidden="true" tabindex="-1"></a>  <span class="at">--host</span> 0.0.0.0 <span class="dt">\</span></span>
<span id="cb32-5"><a href="#cb32-5" aria-hidden="true" tabindex="-1"></a>  <span class="at">--port</span> 5000</span></code></pre></div></div>
<p>For this guide, the local filesystem option is enough to learn the concepts.</p>
</section>

<h2 class="anchored" data-anchor-id="logging-your-first-mlflow-run" id="logging-your-first-mlflow-run">Logging your first MLflow run</h2>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb33"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb33-1"><a href="#cb33-1" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> mlflow</span>

<p>Key API pieces:</p>
<ul>
<li><code>mlflow.set_experiment(name)</code>: groups runs under a named experiment (like a project folder).</li>
<li><code>mlflow.start_run()</code>: a context manager — everything logged inside it belongs to one run, and the run is automatically marked “finished” (or “failed”, if an exception is raised) when the block exits.</li>
<li><code>mlflow.log_param(key, value)</code>: logs a single, unchanging hyperparameter.</li>
<li><code>mlflow.log_metric(key, value, step)</code>: logs a time-series value — directly analogous to <code>writer.add_scalar</code>.</li>
</ul>
<p>Run <code>mlflow ui</code> and open the browser to see this run listed, with its parameters and a metric chart.</p>
</section>

<span id="cb34-17"><a href="#cb34-17" aria-hidden="true" tabindex="-1"></a></span>

<span id="cb34-19"><a href="#cb34-19" aria-hidden="true" tabindex="-1"></a>batch_size <span class="op">=</span> <span class="dv">32</span></span>
<span id="cb34-20"><a href="#cb34-20" aria-hidden="true" tabindex="-1"></a>num_epochs <span class="op">=</span> <span class="dv">10</span></span>
<span id="cb34-21"><a href="#cb34-21" aria-hidden="true" tabindex="-1"></a></span>

<span id="cb34-23"><a href="#cb34-23" aria-hidden="true" tabindex="-1"></a>    mlflow.log_params({<span class="st">"lr"</span>: lr, <span class="st">"batch_size"</span>: batch_size, <span class="st">"num_epochs"</span>: num_epochs})</span>

<span id="cb34-38"><a href="#cb34-38" aria-hidden="true" tabindex="-1"></a>            global_step <span class="op">+=</span> <span class="dv">1</span></span>
<span id="cb34-39"><a href="#cb34-39" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb34-40"><a href="#cb34-40" aria-hidden="true" tabindex="-1"></a>        model.<span class="bu">eval</span>()</span>

<span id="cb34-45"><a href="#cb34-45" aria-hidden="true" tabindex="-1"></a>                val_loss_total <span class="op">+=</span> criterion(preds, yb).item() <span class="op">*</span> xb.size(<span class="dv">0</span>)</span>
<span id="cb34-46"><a href="#cb34-46" aria-hidden="true" tabindex="-1"></a>                correct <span class="op">+=</span> (preds.argmax(dim<span class="op">=</span><span class="dv">1</span>) <span class="op">==</span> yb).<span class="bu">sum</span>().item()</span>

<section id="logging-gradient-flow-weights-and-other-artifacts-in-mlflow" class="level2">
<h2 class="anchored" data-anchor-id="logging-gradient-flow-weights-and-other-artifacts-in-mlflow" id="logging-gradient-flow-weights-and-other-artifacts-in-mlflow">Logging gradient flow, weights, and other artifacts in MLflow</h2>
<p>MLflow’s <code>log_metric</code> is scalar-only, so for anything richer (histograms, gradient-flow figures, images), the pattern is: build the visualization with a library like Matplotlib, save it to a file, and log that file as an <strong>artifact</strong>.</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb35"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb35-1"><a href="#cb35-1" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> matplotlib.pyplot <span class="im">as</span> plt</span>

<span id="cb35-5"><a href="#cb35-5" aria-hidden="true" tabindex="-1"></a>    avg_grads, layers <span class="op">=</span> [], []</span>
<span id="cb35-6"><a href="#cb35-6" aria-hidden="true" tabindex="-1"></a>    <span class="cf">for</span> name, param <span class="kw">in</span> named_parameters:</span>

<section id="the-mlflow-ui-comparing-runs" class="level2">
<h2 class="anchored" data-anchor-id="the-mlflow-ui-comparing-runs" id="the-mlflow-ui-comparing-runs">The MLflow UI: comparing runs</h2>
<p>Start the UI:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb39"><pre class="sourceCode bash code-with-copy"><code class="sourceCode bash"><span id="cb39-1"><a href="#cb39-1" aria-hidden="true" tabindex="-1"></a><span class="ex">mlflow</span> ui <span class="at">--backend-store-uri</span> file:./mlruns</span></code></pre></div></div>
<p>In the browser, you’ll see a table of all runs in an experiment, one row per run, with columns for every logged parameter and metric. <section id="the-model-registry" class="level2">
<h2 class="anchored" data-anchor-id="the-model-registry" id="the-model-registry">The Model Registry</h2>
<p>Once you’ve found a run you’re happy with, MLflow lets you promote its logged model into a <strong>registry</strong> — a separate, versioned catalog of models with lifecycle stages.</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb40"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb40-1"><a href="#cb40-1" aria-hidden="true" tabindex="-1"></a>result <span class="op">=</span> mlflow.register_model(</span>
<span id="cb40-2"><a href="#cb40-2" aria-hidden="true" tabindex="-1"></a>    model_uri<span class="op">=</span><span class="st">"runs:/&lt;RUN_ID&gt;/model"</span>,</span>
<span id="cb40-3"><a href="#cb40-3" aria-hidden="true" tabindex="-1"></a>    name<span class="op">=</span><span class="st">"my_classifier"</span>,</span>
<span id="cb40-4"><a href="#cb40-4" aria-hidden="true" tabindex="-1"></a>)</span></code></pre></div></div>
<p>Or directly during logging:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb41"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb41-1"><a href="#cb41-1" aria-hidden="true" tabindex="-1"></a>mlflow.pytorch.log_model(</span>
<span id="cb41-2"><a href="#cb41-2" aria-hidden="true" tabindex="-1"></a>    model,</span>
<span id="cb41-3"><a href="#cb41-3" aria-hidden="true" tabindex="-1"></a>    artifact_path<span class="op">=</span><span class="st">"model"</span>,</span>
<span id="cb41-4"><a href="#cb41-4" aria-hidden="true" tabindex="-1"></a>    registered_model_name<span class="op">=</span><span class="st">"my_classifier"</span>,</span>
<span id="cb41-5"><a href="#cb41-5" aria-hidden="true" tabindex="-1"></a>)</span></code></pre></div></div>
<p>From the UI (or API), you can then tag versions as <code>Staging</code> or <code>Production</code>, and load the “current production model” by name rather than by a specific run ID or file path:</p>
<div class="code-copy-outer-scaffold"><div class="sourceCode" id="cb42"><pre class="sourceCode python code-with-copy"><code class="sourceCode python"><span id="cb42-1"><a href="#cb42-1" aria-hidden="true" tabindex="-1"></a><span class="im">import</span> mlflow.pytorch</span>
<span id="cb42-2"><a href="#cb42-2" aria-hidden="true" tabindex="-1"></a></span>
<span id="cb42-3"><a href="#cb42-3" aria-hidden="true" tabindex="-1"></a>model <span class="op">=</span> mlflow.pytorch.load_model(<span class="st">"models:/my_classifier/Production"</span>)</span></code></pre></div></div>
<p>This is the piece with no TensorBoard equivalent at all — TensorBoard has no concept of “the model,” only the metrics you chose to visualize.</p>

<section id="part-4-tensorboard-vs.-mlflow-choosing-or-combining-them" class="level1">
<h1>Part 4: TensorBoard vs.&nbsp;MLflow — Choosing (or Combining) Them</h1>
<table class="caption-top table">
<colgroup>
<col style="width: 33%">
<col style="width: 33%">
<col style="width: 33%">
</colgroup>
<thead>
<tr class="header">
<th></th>
<th>TensorBoard</th>
<th>MLflow</th>
</tr>
</thead>
<tbody>
<tr class="odd">
<td>Primary purpose</td>
<td>Visualization</td>
<td>Experiment tracking + lifecycle management</td>
</tr>
<tr class="even">
<td>Setup</td>
<td>Zero-config, just point at a log dir</td>
<td>Needs a tracking URI (local folder or server)</td>
</tr>
<tr class="odd">
<td>Metric logging</td>
<td><code>add_scalar</code>, <code>add_histogram</code>, etc.</td>

</tr>
<tr class="odd">

<td>Native, built-in tabs</td>

</tr>
<tr class="even">

<td>Managing many experiments, reproducibility, deployment handoff</td>
</tr>
</tbody>
</table>
<p>In practice, many teams use <strong>both</strong>: TensorBoard for the rich, moment-to-moment visual debugging of gradients/weights/images during development, and MLflow as the system of record for every experiment’s parameters, final metrics, and model artifacts. PyTorch Lightning makes this combination essentially free, since <code>logger=[tb_logger, mlf_logger]</code> sends every <code>self.log()</code> call to both simultaneously.</p>

<section id="closing-notes" class="level1">
<h1>Closing Notes</h1>
<p>The single most valuable habit to build from this guide isn’t any specific API call — it’s logging <em>more than just the loss</em>. A loss curve going down tells you training isn’t broken, but it doesn’t tell you <em>why</em> something is slow to converge, unstable, or plateauing. Gradient norms, weight histograms, learning rate curves, and GPU utilization together turn a black box into something you can actually debug. Start with TensorBoard for local, visual work; reach for MLflow once you’re running enough experiments that you need to search and compare them systematically, or once you need to hand a trained model off to someone else in a reproducible way.</p>
